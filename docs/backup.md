# Respaldo y restauración

La PWA permite descargar una copia JSON de los agregados locales que la persona seleccione. Antes de descargar se puede marcar uno, varios o todos los créditos y asignar un nombre al archivo. El nombre inicial `cuotaclara-respaldo-AAAA-MM-DDTHH-MM-SS-sssZ.json` incorpora el timestamp UTC para reducir colisiones. El respaldo incluye versión de esquema, fecha de creación, préstamos, pagos y snapshots de escenarios; los importes se representan como texto decimal. La versión actual de respaldo es **6**: conserva contratos v2 heredados, el contrato v3 con cuota total y seguro, varios saldos conciliados, la fecha final bancaria única y la identidad interna y referencia externa de pagos importados, sin serializar objetos `Money` como números.

Al restaurar versiones 1 a 5, un pago CSV conserva su antiguo `id` como identidad interna y también lo adopta como referencia externa. La versión 6 valida que las identidades internas no se repitan entre préstamos y que una referencia externa no se repita dentro del mismo préstamo antes de solicitar confirmación.

Al seleccionar una copia para restaurar, `@cuotaclara/backup` valida el JSON completo, su versión, préstamos únicos, pagos, monedas y pertenencia de escenarios antes de permitir escoger cuáles créditos restaurar. La confirmación indica cuántos préstamos seleccionados serán restaurados y advierte que coincidencias por identificador se reemplazarán. Una copia inválida no modifica la persistencia.

La restauración acepta copias v1 heredadas, v2 y v3. Una copia v1 no recibe plazo ni seguro inventados; se restaura como préstamo heredado. Una copia v2 conserva su semántica de cuota base y no se convierte automáticamente a v3. La restauración guardada usa el repositorio local por agregado. Una falla física de IndexedDB durante esa fase se informa a la persona usuaria; conservar una copia descargada antes de restaurar sigue siendo recomendable.
